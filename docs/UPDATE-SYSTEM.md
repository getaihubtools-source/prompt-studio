# سیستم آپدیت Prompt Studio

## ریشهٔ تأخیر (یافته‌ها)
1. **Workbox + کش HTML با revision ثابت**: ناوبری همیشه از precache (cache-first) جواب می‌گرفت؛ نسخهٔ جدید فقط پس از نصب SW جدید + بستن کامل همهٔ تب‌ها/APK اعمال می‌شد.
2. **GitHub Pages با `Cache-Control: max-age=600`**: sw.js و HTML تا ۱۰ دقیقه از CDN/مرورگر کهنه می‌آمدند؛ مرورگر هم بررسی آپدیت SW را بدون تلاش مجدد انجام می‌داد.
3. **تشخیص آپدیت فقط هنگام load**: برنامهٔ نصب‌شده/APK ماه‌ها در پس‌زمینه می‌ماند و هیچ بررسی‌ای انجام نمی‌شد.
4. **بدون نسخهٔ قابل‌مشاهده**: نه کاربر نه شما نمی‌دانستید چه build‌ای اجرا می‌شود.
5. **APK (TWA)** همان Chrome/SW را استفاده می‌کند؛ پس مشکل APK همان مشکل SW بود. فقط تغییر manifest/آیکن نیاز به بازبسته‌بندی دارد.

## معماری جدید
| لایه | رفتار |
|---|---|
| `sw.js` | کش نسخه‌دار `ps-<BUILD>`؛ HTML/license-config/manifest **network-first** (مهلت ۳٫۵ ثانیه، بعد کش)؛ آیکن‌ها cache-first؛ نصب اتمی با `cache:'reload'`؛ پاک‌سازی کش‌های قدیمی در activate |
| ثبت SW | `updateViaCache:'none'` → sw.js هرگز از کش HTTP خوانده نمی‌شود |
| `version.json` | `{build,time,force,notes}` با `no-store` خوانده می‌شود (SW دستش نمی‌زند) |
| Update Manager (`window.UM`) | بررسی: هنگام باز شدن، بازگشت به برنامه، آنلاین‌شدن، هر ۳۰ دقیقه، دستی. اگر version.json جدید باشد ولی CDN هنوز کهنه، تا ۸ بار هر ۴۵ ثانیه دوباره تلاش می‌کند |
| اعمال | خودکار اگر: تب پنهان، یا ۱۵ ثانیهٔ اول باز شدن، یا `force` — و **هیچ ویرایش ذخیره‌نشده‌ای نباشد**؛ وگرنه اعلان «نسخهٔ جدید آماده است» با دکمهٔ به‌روزرسانی. محافظ ضد حلقهٔ ریلود (۳ بار/دقیقه) |
| تنظیمات ← «به‌روزرسانی برنامه» | نمایش build، آخرین بررسی، «بررسی»، «اعمال»، و «به‌روزرسانی کامل» (SW + کش پاک می‌شود، **IndexedDB دست‌نخورده**) |

## انتشار هر نسخه
- دستی: `node tools/stamp.js [--force] [--notes "متن"]` سپس push.
- خودکار: `deploy/pages.yml` را به `.github/workflows/` ببر؛ stamp در CI انجام می‌شود (و گزینهٔ force در Run workflow).
- BUILD هش محتوای همهٔ فایل‌هاست؛ بدون تغییر محتوا، BUILD تغییر نمی‌کند.
- اگر فایل جدیدی به PRECACHE اضافه کردی، فهرست `PRECACHE` در sw.js را هم به‌روز کن (stamp وجود فایل‌ها را چک می‌کند).

## APK
- آپدیت محتوا **نیاز به ساخت APK جدید ندارد**.
- این انتشار آیکن/رنگ manifest را تغییر داده → یک‌بار APK را با **همان keystore** و **versionCode بالاتر** دوباره بسازید.
- نصب‌های قدیمی (Workbox) با اولین آپدیت، اعلان قدیمی را می‌بینند؛ بعد از یک‌بار زدن «به‌روزرسانی» به سیستم جدید مهاجرت می‌کنند.

## محدودیت‌ها
- GitHub Pages خودش ~۱۰ دقیقه CDN cache دارد؛ حداقل تأخیر واقعی همین است (سیستم تکرار خودکار دارد).
- تست‌ها روی Chromium انجام شده؛ iOS Safari رفتار SW را کندتر اجرا می‌کند.
